## 一、这是什么项目

三国题材的伪 3D 策略游戏，纯 Web、单机，**只给自己和同学玩，不打算上架**（所以技术选型上不需要考虑商店审核、多平台打包之类的事）。

核心设定：**同一个乱世，三个不同的位置** —— 主公、城池官长、领兵武将。玩家能从下往上爬：升迁、叛逃、甚至自立成一方诸侯，切换到主公玩法。三条线共用同一套世界规则（NPC 官长/武将跑的是玩家能跑的那一套）。

完整设计方案见 [`docs/设计方案-v2.md`](../docs/设计方案-v2.md)，项目说明见 [`README.md`](../README.md)。

## 二、三条不许违反的硬规则（写在记忆里，每次都要守）

1. **不做数值面板**。不摆一排「攻击力 82 / 防御力 65」这种条子，用画像 + 评语 + 擅长标签表达人物；仗打完给的是「折了多少人、赢在哪一步」这种叙述性战报，不是伤害数字。
2. **资源是对象，不是数字堆**。粮、钱、户口、民心、守备都要有对应的**视觉呈现**（城里能看见田、仓、人），不是纯 HUD 上的一个数。
3. **楔子只改权重，不无中生有**。天灾人祸、突发事件这类东西，只能去改已有机制的触发概率/幅度，不能凭空造一条新规则岔出去。

技术上的四条硬规则（README 里写着，同样不许破）：
1. 模拟层必须确定性（同种子+同命令流=逐位相同结果），零依赖、不碰渲染/DOM
2. 所有状态变更走命令（dispatch），表现层只读快照
3. 推导值绝不存进状态，每次从源头重新算
4. 任何时刻屏幕上不超过五个可操作项，不做教程弹窗，用「上级的命令」当教程

## 三、技术栈与目录结构

```
content/       全部游戏内容（JSON，Vite 热重载，改数值不用重启）
src/sim/       模拟层 —— 纯 TS，零依赖，确定性引擎，禁止碰渲染
src/view/      表现层 —— Three.js，geometry/material 全代码生成，零外部美术资源
src/ui/        React 覆盖层，只读 engine.getState()，只能 dispatch 命令
src/audio/     Web Audio 现场合成音效，没有音频文件
tools/         推演/平衡工具（node tools/xxx.ts 直接跑，不进构建）
tests/         node:test，纯模拟层测试，跑得飞快
```

跑法：
```bash
npm install
npm run dev       # http://localhost:5273
npm run verify    # 边界检查 + 类型检查 + 全部测试（提交前必跑）
npm run balance / world / battle / field / lord   # 各种推演工具
```

## 四、已经做完的（M1 → M4，全部 ✅）

**M1 一城之治**：一座城 5×5 地块、11 种建筑、粮/钱/户口/民心/守备、季度指标交差、天灾人祸。

**M2 天下图与部队**：十二城五势力会自己发育出兵、部队在图上真走会耗粮会溃散、围城是耗不是秒杀、主公会派援军、两种败法（城破/被撤职）。

**M3a/b 守城战与野战**：流寇 → 正规军强攻两级压力、战前部署（城头/城门/预备）、战中决断、看得见的战场（九列七行格子、坡林沼河滩、五种阵型）、出城迎击的取舍。

**M3c 武将身份**：屯兵地（招兵练兵修设施招将并行）、主公军令（可抗命）、出兵点将（战场图上分兵伏兵偷袭）、细作侦查（真假情报难辨）、**单挑**（勇力算数但不是算术题，输了要么阵亡要么伤退，一仗只斗一次，界面上会自动停拍等玩家决断）。

**M4 主公与任命**：
- **人物库**：`content/people.json`，`idx.person` / `idx.byFaction` 索引
- **任命**：`state.posts`（城 id → 人物 id），`wardenOf()` 查询，城易主会自动指派新守将（`appointWarden`），玩家可以「举荐」帐下武将去守一座空城
- **外交**：`FactionState.attitude` 现在真的会变——打了会结仇、共同敌人拉近关系、强邻招人忌惮（这是防滚雪球的机制）、旧怨会随时间淡化。`atWar()` 判断是否敌对
- **主公身份可玩**：新增 `role: 'lord'`，`src/sim/handlers_lord.ts` 四个动词——任命守将、征调各城之兵、拨粮兴修、遣使；`src/ui/Lord.tsx` 整个新界面（辖境列表、点城下令）；`tools/lord.ts` 推演工具验证四个动词都真的算数

这一路上抓出了好几条**「机制看着在跑、其实从来没生效过」**的 bug，教训已经写进记忆文件 [`dead-mechanic-audit.md`]：
- `nodeDefence` 原来根本不看守将——任命在机制上等于零，现在改成城防乘数（以 1.0 为轴，别写成往上加，写成加会把全天下城防抬高、显得玩家的城更弱）
- AI 会连玩家自己那家也代打——当主公的玩家什么都不做地盘也在长，改成玩家的势力排除在 AI 自动出兵逻辑外
- 主公被拖进「只认一座城」的守城战小游戏，导致 `cmdDay` 卡死在开局第 61 天不动——改成主公专属的日结算分支
- `begin` 命令原本只认 `lords.json` 里已定义好的诸侯，其余诸侯选不了——现在从 `content/factions.json` 派生
- 征调这个动词一开始不存在，没有它主公永远打不过 NPC（NPC 出兵是整个势力一起算的，玩家原本只能一城一城手动调），现在有了 `lord_muster` 命令

当前 **121/121 测试全绿**（`npm run verify`）。
