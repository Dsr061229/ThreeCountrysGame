# 三国题材 2.5D 游戏 — 设计方案 v0.1

> 状态：待确认。确认后进入 M0。

---

## 一、设计支点（为什么不一样）

市面三国游戏的通病不是"做得差"，是**玩家定位错了**：让你当操盘手，你和世界的关系就只剩数字增减。

本作的支点：

> **你是身处历史缝隙中的一个人。你的力量来自「你知道什么」和「谁欠你人情」，而不是「你的武力值是多少」。**

由此推出三条硬规则，全程不许违反：

1. **不做全局数值面板**。玩家永远看不到"我方综合国力 87"这种东西。你只能通过见到的人、听到的话、看到的景象来推断天下形势。
2. **核心资源是对象，不是数字**。"关羽欠你一次"是一个可以被花掉的具体物件，带上下文、带时效；不是好感度 +5。
3. **每次改变世界，都要能说出因果链**。"因为我把那封信送到了荀彧手里，所以曹操提前动了，所以官渡打早了两个月"——玩家必须能复述出这句话。

## 二、三大核心系统

### 2.1 情报（Knowledge）

情报是**对象**，不是解锁标记。每条情报有：

| 字段 | 说明 |
|---|---|
| 内容 | "袁绍屯粮于乌巢" |
| 真伪 | 真 / 假 / 半真（玩家未必知道） |
| 时效 | 过期作废，或变成"旧闻" |
| 来源 | 谁告诉你的，可追溯（泄密会被查到） |
| 敏感度 | 传播出去的风险等级 |

可执行操作：**打探、验证、传播、隐瞒、伪造、栽赃**。

情报是小人物撬动天下的唯一杠杆。你打不赢一场仗，但你能决定谁先知道。

### 2.2 人情（Obligation）

不是好感度条。是一张**具名欠条**：

```
[人情] 张飞 → 你
  缘由：你在涿郡替他顶了一次牢狱之灾
  分量：重（可兑现一次高风险请求）
  时效：无限期，但会因你的背叛行为作废
```

- 可兑现（花掉就没了）、可转让（我向A讨人情，替B办事）、可积累
- 反向也存在：**你欠别人的**。被催债时会触发被动事件
- 同时存在 **仇家（Grudge）** 系统，结构对称。你救的每个人背后可能有一个记恨你的人

### 2.3 名声（Reputation）— 多维且失真

不是一个数字。是 **5 个维度 ×"传播中失真"**：

- 维度：忠 / 义 / 智 / 勇 / 诡
- 每个势力、每个圈层（士族 / 军中 / 市井 / 黄巾余部…）对你的印象**独立存储**
- 传播有延迟和变形：你在南阳做的事，三个月后传到许都会走样。可以**主动利用**——散布关于自己的假消息

## 三、"间接影响天下"的具体机制

这是全案最关键的一环，必须是机制，不能是文案。

### 3.1 天下棋盘（World Sim）

一个规则驱动的模拟层，玩家看不见它的界面：

- **节点**：州/郡。属性含 粮、兵、民心、治安、守将、士族倾向
- **势力**：有 **意图栈**（目标 + 优先级），如"曹操：稳固兖州 > 拉拢颍川士族 > 试探袁绍"
- **时钟**：以 **旬（10日）** 为单位推进。每旬结算 征兵 / 屯田 / 出兵 / 结盟 / 叛乱 / 谣言扩散

### 3.2 楔子（Wedge）—— 玩家的介入方式

**玩家的行动不直接改数值，而是改「势力AI的决策权重」。** 这是本作的核心技术设计。

举例：

| 玩家行动 | 生成的楔子 | 世界的反应 |
|---|---|---|
| 把"乌巢屯粮"送到曹营谋士手中 | 曹操意图栈中「奇袭」选项权重 5% → 60% | 曹军可能提前出兵，官渡战局改写 |
| 在某郡剿匪成功 | 该郡治安↑；太守欠你人情；匪首兄长成为仇家 | 太守日后可能保你一次；仇家会来找你 |
| 替某士族写檄文 | 该士族在该州舆论↑；对立士族记你一笔 | 士族倾向变化，影响该郡是否倒戈 |
| 散布"某将军通敌"的假情报 | 该将军所属势力信任度↓ | 可能被调离、被杀、或反查到你头上 |

因为是改权重不是改结果，玩家看到的永远是 **"人做了决定"**，而不是 **"数字变了"**。沉浸感来源于此。

### 3.3 史实锚点 + 漂移

- 历史大事件有 **预定发生窗口** + **前置条件集**
- 玩家可以**破坏或加固**前置条件
- 结果：官渡之战一定会打（锚点），但可能提前 / 推迟 / 换地方 / 一方主帅换人（漂移）
- 既保留三国味，又不是固定剧本

## 四、身份与文武路线

### 4.1 开局身份选择

不是选职业，是选**你在乱世中的起点位置**。每个身份决定：起始郡、初始人脉、可用动词、初始情报、社会阶层。

候选身份（首发 6 个，各带独立开场）：

| 身份 | 起点 | 特点 |
|---|---|---|
| 游学士子 | 颍川 | 文路。人脉起点高，武力为零，能接触士族圈 |
| 边郡义从 | 涿郡 | 武路。有武艺和一队伙伴，但没有门路 |
| 郡吏文书 | 陈留 | 文路。掌握公文与账目，天然的情报节点 |
| 商队护卫 | 南阳 | 武路。机动性最强，跨郡跑，见闻广 |
| 黄巾余部 | 冀州 | 起点最低，被通缉，但底层网络无人能比 |
| 没落士族子弟 | 汝南 | 有名无实，家道中落，名声是资产也是包袱 |

### 4.2 文 / 武 不是数值树，是**动词集**

| | 文 | 武 |
|---|---|---|
| 核心动词 | 察言、书信、辩论、断案、理账、荐举 | 比武、护卫、追踪、剿匪、率队、单挑 |
| 情报获取 | 从文书、谈话、账目里读出来 | 从现场、痕迹、俘虏嘴里问出来 |
| 施加影响 | 说服决策者 | 改变既成事实 |

**共用**情报 / 人情 / 名声三大系统。中后期可交叉解锁（文人习武、武人识字），但成本高、耗时长——避免后期变成"全能数值怪"。

### 4.3 三国人物的解锁

不是抽卡、不是"招募到队伍"。是 **关系的推进**：

```
陌路 → 面善 → 相识 → 可托付 → 生死之交
```

- 每个历史人物有 **接近条件**（在对的时间出现在对的地方 + 对的名声维度 + 对的中间人）
- 关系推进解锁的是 **该人物愿意为你做的事**，而不是"他加入你的队伍"
- 例：和荀彧到"可托付"，你的情报能直达曹操案头；和张飞到"生死之交"，他会为你打一架不问缘由
- 历史人物会**独立行动、会死、会背叛**。他们不是你的卡牌

## 五、战斗与对抗形式

### 5.1 单挑 —— 架势对决（Stance Duel）

不是数值互砍。是**读招博弈**：

- 三种架势：**攻 / 守 / 诱**，互相克制但不是石头剪刀布——加入 **气（体力）** 和 **破绽窗口**
- 对手有 **tell**（预备动作、微表情、脚步），玩家要读
- 武将之所以强，是因为 **tell 更难读、招式库更大、假动作更多**，不是血条更长
- 单次交换 2–5 秒，一场对决 30–60 秒。**输了有后果，不是读档重来**（可以受伤、被俘、破相、失去名声）

### 5.2 群战 —— 小队战术（Squad Tactics）

- **6–8 人小队**，等距网格，回合制
- 你是小人物，你带的是"一什一伍"，不是十万大军
- 关键变量：地形、阵型、士气、指挥链（你的传令能不能到位）
- 士兵是有名字的人，会死，会怕，会溃

### 5.3 文路对抗 —— 辩论（Debate）

文路线的"战斗"，是一个**信息不对称的小型博弈**：

- 对方有 **立场支柱**（3–4 根），你要用手上的情报牌逐一击破
- 对方也有 **底牌**（你不知道的情报），可能反将你一军
- 可以输。输了不是 Game Over，是"这条路走不通了，换一条"

## 六、美术方向

推荐：**宋画写意 + 低模几何 + 后处理 Shader**

- 场景：3D 低多边形模块化建筑（夯土墙、木构、瓦顶、市集），几何极简
- 角色：低模 + 卡通/水墨着色
- **表现力主要来自 Shader**：纸纹底、墨线描边、留白雾气、时辰与季节的整体调色
- 摄像机：斜俯视固定角度（可小幅旋转），2.5D 观感

**为什么选这个**：美术工作量可控、风格辨识度高、弱化模型精度不足的问题。没有美术团队的情况下，这是唯一能做出"高级感"的路线。

备选：HD-2D（像素 + 景深，八方旅人风格）—— 更省事，但偏复古。

## 七、单机与联机

**诚实的工程建议：单机为主干，联机是"同一个世界换个驱动方式"，不是第二个游戏。**

### 架构要求（从第一行代码就要遵守）

1. **模拟层（Sim）与表现层（View）彻底分离**。Sim 不引用任何渲染代码
2. **所有状态变更走命令（Command）**。没有任何地方直接改 Sim 状态
3. **Sim 必须确定性**：固定随机种子 + 整数/定点数值，不用浮点参与逻辑判定
4. 存档 = 初始种子 + 命令流（回放即存档）

有了这三条：
- 单机 = 本地跑 Sim
- 联机 = 权威服务器跑 Sim，客户端发命令、收状态差分

### 联机玩法

- **2–6 人共处同一个乱世**，各自扮演不同小人物
- 可以相遇、结义、合作、也可以互为仇家
- 世界模拟共享——A 玩家改变的天下，B 玩家会遇到
- **不做实时同步的动作战斗**（成本高、体验差）。联机中的对决用回合/半回合制

## 八、内容生产（不依赖外部 AI）

全部靠 **预设内容 + 规则重组**，这也是 CK3 / RimWorld / Caves of Qud 的做法：

| 层 | 做法 |
|---|---|
| 数据 | 人物、事件、对话、条件全部 JSON / 自定义 DSL，可热重载 |
| 事件系统 | 条件表达式 + 权重 + 冷却 + 后果（命令列表） |
| 对话 | 模板 + 变量替换 + 语气/立场变体。NPC 说什么 = f(性格, 情绪, 对你态度, 他知道什么) |
| NPC 行为 | **效用 AI（Utility AI）**：每个 NPC 有欲求（权力/安全/名声/财/义），对每个可选行动打分 |

效果：NPC 看起来"有自己的想法"，叙事从系统交互中**涌现**，而不是靠堆写死的剧本。

## 十、技术栈（已定）

**纯 Web，不做引擎迁移。** 决策依据：不上架、玩家是自己和几个同学 —— Godot 的全平台导出、Steam、性能上限这些优势全部不成立，只剩成本。

| 层 | 选择 | 约束 |
|---|---|---|
| 模拟层 | 纯 TypeScript，零运行时依赖 | 整数运算 + 种子 PRNG；禁止 import 渲染库、DOM、`Math.random`、`Date.now`。由 `tools/check-boundaries.mjs` 强制 |
| 表现层 | Three.js，正交相机 + 低模 + 墨线描边 | 全部几何由代码生成，不依赖外部模型资源 |
| UI 层 | React 19，HTML 覆盖层 | 只读引擎快照 + 发命令；不含任何规则判断 |
| 构建 | Vite 7 + TS 5.9 | JSON 内容热重载 |
| 联机（M3） | Node + ws，权威服务端 | 复用同一份 Sim |

发链接就能玩，这正是 Web 最强的场景。

**已验证的核心闭环**（实测日志）：

```
得知：太平道定于三月五日甲子举事，天下三十六方同起。（自褐衣道人处）
你把「太平道定于三月五日甲子举事…」说给了钟繇。
你把太平道举事的日子送到了钟繇手上。郡府开始考虑先下手。
这话太重了。钟繇听完看了你一眼——他会记得是谁说的。
汉室朝廷在颍川郡大举搜捕。
```

不送情报时，官府「搜捕」的意图权重是 2（对比总权重 87，几乎不发生）；送出后五旬内触发三次。
**玩家没有改任何数字，改的是一个人的决定。**
