# 主公玩法方案 · v1「案头」

> 这份东西要解决的是一句写在代码里的实话 —— [`handlers.ts:391`](../src/sim/handlers.ts) 那一段：
>
> > 主公的一天里，他自己什么也不做。
>
> 当时那是设计意图。现在它是病因。

---

## 零、一句话

**主公现在是一只操作天下的手，方案要把他改成一个只能靠别人办事的人。**

他手里真正稀缺的资源从来不是粮和兵 —— 是**人**，而人有自己的心思、自己的私账、
自己那一套「主公若不允我，我便自己看着办」。

---

## 一、诊断：现在为什么无聊

四个动词全在 [`handlers_lord.ts`](../src/sim/handlers_lord.ts) 里，毛病也全在那儿。

### 1.1 没有一件事会跟你还价

| 动词 | 现在的实现 | 唯一的阻力 |
|---|---|---|
| 任命 | `state.posts[cityId] = personId` | 无 |
| 兴修 | `node.grain -= cost; node.dev += 1` | 粮不够 |
| 遣使 | `attitude += 18`，永远成功 | 粮不够 |
| 征调 | 一键抽空全境余兵 | 粮不够 |

天下没有任何东西会拒绝主公。任命不问那个人愿不愿意去，遣使不问对方肯不肯见，
征调不问守将舍不舍得放兵。**每一步都不是决策，只是点。**

### 1.2 没有「等消息」

除行军外全是当场结算。主公这一身份的味道本该是**下了令，然后等** ——
等回报、等坏消息、等有人阳奉阴违。现在是即时反馈的建造游戏。

### 1.3 下属没有意志

武将线做了[「军令可抗命」](../src/sim/order_types.ts)，还专门写了
「不能拒的命令不是选择，是任务栏」。主公线反过来 —— 看不见任何抗命、请战、
献策、伸手要粮、互相不和。`idlePeople()` 就是 `byFaction` 减去已任命的，
人物只是任命槽的填充物。

`people.json` 里明明躺着 `temper` / `loyalty` / `flaw` / `praise` / `note`，
全都没有行为接上去 —— 这是新一条「有数据没行为」，
和记忆里 `dead-mechanic-audit` 抓过的那几条一模一样。

### 1.4 界面没有中间层

主公在做的事是「点开十二座城，每座点四个按钮」—— 十二份缩水版的城池官长活。
既没有微操的乐趣，也没有战略的高度。

### 1.5 三条线的对称缺了一角

- 城池官长：上头**按季下指标**追着他跑
- 领兵武将：上头**隔一阵下军令**追着他跑
- 主公：**没有任何东西追着他跑**

不是主公该没有压力 —— 是主公的压力应该从**下面**来，而这一半从来没写。

---

## 二、方案：核心循环

```
        案上摞着几件事  →  你只能允一部分  →  人记着你允了什么
              ↑                                      ↓
        他下一次怎么替你办事  ←  心气 / 私账 / 派系  ←  他自己去办（会走样）
```

一条纪律：**主公不再有「按钮」，他只有「答复」。**

现在那四个动词不删，但它们不再是你想点就点的东西 ——
它们变成你对某个人某件呈报的回应。兴修不是你点的，是**有人请你拨粮**；
出兵不是你点的，是**有人请战**。

这一改的直接后果是：屏幕上永远只有三到五件事，
正好压在「任何时刻不超过五个可操作项」那条硬规矩上 —— 而且是自然压住的，不是砍出来的。

---

## 三、系统一 · 幕府案头（这条线的心跳）

### 3.1 是什么

默认屏不再是天下图，是**一张案**。案上摞着三到五件帖子，每件是帐下某个人
（或别家的使者）呈上来的一件事。你逐件批。批完这一摞，天数往前走，
过些日子再摞上新的。

这是把武将线的 `LordOrder` **反过来写**：那边是主公派活给你，这边是下属向你请令。
两边共用同一套「有期限、可拒、拒了有代价」的骨架。

### 3.2 呈报有哪些（全部从天下实况里长出来）

沿用军令那条硬规矩 —— **呈报要有道理**。主公不会收到凭空的请求，
每一件都能在 `state` 里指到具体的城、具体的敌、具体的人。

| 呈报 | 触发条件（看的是现成的状态） | 允了会怎样 | 不允会怎样 |
|---|---|---|---|
| **请战** | 某守将的城挨着一座敌城，且己方余兵够 | 他自领兵去打，走现成的 `marchArmies` | 心气 −，性急（`rash`）的掉双倍；连拒三次他可能自己动手 |
| **请粮** | 某城 `grain` 低于警戒 / 歉收 / 被围 | 治所发粮车，**在图上走**，到了才入库 | 那城的 `morale` 与守备一路下滑 |
| **请援** | `state.sieges[cityId]` 存在 | 邻城出兵解围（复用现成围城逻辑） | 城多半会破，而且**全帐下都记着你没救** |
| **举荐** | 举荐者 `good` 里含「举荐」，且望够高 | 一个在野的人入你帐下 —— **这是招人的主要途径** | 举荐者心气 −，那个人被别家收走 |
| **告状** | 甲乙分属不同派系、或有一方心气低 | 你要查、要罚、还是压下去 —— 三条路都得罪人 | 拖着，两人心气都掉 |
| **求去** | 某人心气跌破线 | 放他走：少一个人，但不结仇 | 不放：他叛逃的权重开始涨 |
| **献策** | 献策者 `wit` 高且 `good` 含「谋断」 | 一条**只改权重**的计（见 §3.4） | 无损失，但那条计的窗口过去了 |
| **来使** | 别家 `attitude` 到某个区间 | 接下条款（借道 / 共伐 / 求和 / 索粮 / 要人） | 对方 attitude − |

每一件帖子上写的是**那个人的话**，不是参数：

```
　濮阳　张郃　　　　　　　　　　　　　　　　　　　　　二十日前
　「东边鄄城守兵不过千余，某愿以本部三千往取之。
　　迟则曹氏必增其戍。」

　　　　　　　　　　　　　　　　［　允　］［　留中　］［　不许　］
```

### 3.3 三条纪律

**一、批不完是常态。** 案上一次只放得下几件，多的自动过期。
地盘越大呈报越多 —— 「城多了管不过来」到这里第一次真的成立，
而不是靠「闲人不够」这种其实一直够用的假压力。

**二、不批也是一种批。** 留中不发不是免费的中立选项：
请援的城会破，请战的人会自己动手，求去的人会不告而别。
**没有「等下一回合再说」这个选项。**

**三、你批的是话，不是数。** 帖子上不出现「守备 +12」，
出现的是「迟则曹氏必增其戍」。要不要信他，是玩家的判断，不是玩家的算术。

### 3.4 献策 = 「楔子只改权重」的正式出口

献策不新增机制，它只拧现成的旋钮：

- **屯田** → `growNodes` 里那家的粮增速 +，但当年兵源 −
- **离间** → 敌方两家之间的 `attitude` 恶化，其援军判定打折
- **纵反间** → 敌方某守将心气 −（NPC 也跑心气这一套）
- **广施恩信** → 新破之城的 `unrest` 衰减加快
- **深沟高垒** → 己方所有城的 `nodeDefence` 乘数 +，但 `dev` 增长 −

每条都是既有公式上的一个乘数，寿命几十天，到期自己没。
**没有一条会岔出一套新规则。**

## 四、系统二 · 心气与旧账（人怎么变成人）

### 4.1 不做忠诚度条

每个人身上挂两样东西，玩家**只看得见其中一样**：

- **心气**（隐藏的数）：你允了他的事就涨，驳了就跌，久不理会也跌
- **一句状态**（看得见）：「谢主公信重」／「近来沉默寡言」／「称病不出」

数在暗处，话在明处。这是「不做数值面板」最狠的一种用法 ——
**玩家永远不能确切知道一个人还剩几分心，只能听他说话的口气。**

### 4.2 最危险的信号是「不再上报」

心气高的人**呈报频繁**（他还愿意问你）；
心气低的人**呈报变少**；
心气到底的人**一件也不上了** —— 因为他已经决定自己看着办。

所以案头空了不是太平，是出事了。这一条不用任何 UI 提示，
玩家自己会在某一天背后一凉。

### 4.3 私账：每个人要的东西不一样

四种索求，从 `temper` / `good` / `loyalty` 派生：

| 私账 | 他要什么 | 你给对了 | 你给错了 |
|---|---|---|---|
| **名** | 战功、先登、独当一面 | 准他出战 | 给他粮给他城都不领情 |
| **利** | 粮、赏、富庶的城 | 拨粮、赐城 | 让他去打硬仗只会更怨 |
| **位** | 更大的城、更多的兵 | 调他去大城 | 一直放在小县 |
| **义** | 你别做不义的事 | 赈灾、不杀降、守约 | 你屠一次城他就凉一半 |

**允了一件事，只对得上他私账的那一半算数。** 这让「谁请的、准不准」
从「同意 / 拒绝」变成一道真的题。

### 4.4 旧账：你说过的话会被引用

存每个人身上最近 N 条你对他的答复。他下次上报会引用：

> 「主公前年许某取濮阳，至今未发一兵一卒。今某不敢复请。」

实现上就是一个环形数组加几句模板，代价极小，
但它是这条线上唯一会让玩家**记得自己两年前干过什么**的东西。

## 五、系统三 · 派系（把人变成朝堂）

### 5.1 每个人属一个派系

不新造设定，用史上现成的：曹操的**谯沛**（宗亲武人）对**汝颍**（士人谋臣）；
袁绍的**河北**对**颍川**；刘表的**荆襄大族**对**外来客将**。
`people.json` 加一个 `clique` 字段即可。

### 5.2 你批的每一件事在两派间是零和的

准了武人请战，士人那边集体心气 −；准了士人的屯田，武人那边 −。
**你不可能让所有人满意** —— 这是主公这条线上唯一一个不靠敌人制造的压力。

### 5.3 一派独大是内部的滚雪球，也要压

- 强的一派开始**不请令就出兵**（呈报直接变成通报）
- 弱的一派开始**私通**（`attitude` 悄悄向敌方漂移，靠告状呈报暴露）

这是设计方案 §8.1「主公滚雪球」的内部版本：
**不给赢家加惩罚，给赢家加麻烦。**

## 六、系统四 · 令是要传的（距离与假账）

这一条把「主公不亲手做任何一件事」从一句宣言变成一条真约束。

### 6.1 令要走路

你的令从治所发出，按现成的 `MARCH_PER_DAY` 走到那座城才生效。
远城的令要走十几天。

**推论：远城你只能靠人，不能靠令。** 这才是任命之所以重要的机制原因 ——
不是因为守将给城防加了个乘数，是因为你的手根本伸不到那么远。

### 6.2 呈报也是旧消息

帖子上永远标着「二十日前」。你批的时候，那座城可能已经破了。
**战争迷雾的味道，完全建在现成的行军进度上，不需要新系统。**

### 6.3 你看到的兵粮是账，不是实数

主公面板上的「兵 12400　粮 38200」现在是各城**报上来的账**。
心气低的、私账是「利」的、被告过状的守将会**虚报**：多报粮、少报缺额。

于是「告状」这件呈报第一次有了分量 —— 也第一次实现了设计方案里那句
「贪吏 → 粮账对不上，民心暗跌，**你未必立刻发现**」。

派人去查是要花时间的，查错了人得罪一整派。

## 七、系统五 · 名分（主公独有的那样东西）

另外两条线没有、也不该有的东西。这是主公之所以是主公的地方。

### 7.1 望不是数值条，是天下人的评语

显示成一句话：「关东皆称其义」／「人谓其鹰视狼顾」／「无人肯为之死」。

**涨**：赈灾、不杀降、守约、迎奉天子、发檄讨逆、厚葬敌将
**跌**：屠城、背盟、杀名士、纵兵掳掠、坐视盟友被灭

### 7.2 望改的还是现成的权重

| 望高 | 望低 |
|---|---|
| 举荐呈报变多，在野的人主动来投 | 帐下心气基线整体下滑 |
| 盟约不易反复 | 别家更容易结成同盟来打你 |
| 新破之城 `unrest` 衰减快 | 打下来的城一直不服 |

再一次：**没有一条新规则，全是旧公式上的乘数。**

### 7.3 挟天子：一次性的大抉择

天子东归那一年（见 §8），谁离得近谁能迎。迎了之后：

- **得**：可以用朝廷名义对别家下诏（要粮、要地、令其罢兵）。不从者，你讨伐他是「奉诏」——
  打赢望还涨。这是全局唯一一个能让**攻击行为涨望**的开关。
- **失**：天子在你城里是一个麻烦。帐下私账是「义」的人开始跟你离心
  （他忠的是汉不是你），而天下所有诸侯对你的 `attitude` 一起 −。

**这是整局最重的一个决定，而且没有正确答案。**

## 八、系统六 · 时局（给十年一个节奏）

不是随机事件，是历史节点。每一件到来时，天下每一家都要表态，
表态改的仍然是既有权重。

| 年 | 时局 | 你要表的态 |
|---|---|---|
| 初平元年 | 讨董联军 | 出兵 / 观望 / 附董 —— 定你开局的望与仇 |
| 初平三年 | 董卓死，长安乱 | 收西凉散兵 / 不理 |
| 兴平元年 | 大饥（人相食） | 开仓 / 闭仓 —— 望与粮的正面对撞 |
| 兴平二年 | 天子东归 | 迎 / 不迎（§7.3） |
| 建安初 | 青州黄巾 | 剿 / 招降（招降得兵，但那兵不好带） |

每一件都是**全天下同时收到的一道题**，而各家 AI 用它们自己的性格答。
玩家第一次能看见「别人也在做选择」。

## 十、老的四个动词去哪了

| 老动词 | 新位置 |
|---|---|
| 任命 | 留着，但调走一个人**那座城的人会不满**，被调的人也可能不情愿 |
| 兴修 | 变成「请粮 / 请修」呈报的答复。粮车要走路 |
| 征调 | 留着，但各城守将**肯不肯出兵看心气**；低的推诿、打折、虚报 |
| 遣使 | 并进「来使」与外交条款，不再是固定 +18 的按钮 |

一个不删，全都长出了阻力。

## 十一、分期

**M4.5a · 案头与心气**（最小可玩，改完这一期就已经不无聊了）
呈报队列 + 请战 / 请粮 / 请援 / 求去四种 + 心气与一句状态 + 「不再上报」。
不碰派系、名分、距离。

**M4.5b · 派系与距离**
`clique` 字段 + 零和心气 + 令要走路 + 呈报带日期 + 假账与告状。

**M4.5c · 名分与时局**
望 + 五件时局 + 挟天子。

**M4.5d · 献策**
五到八条只改权重的计。放最后是因为它最依赖前面几期的旋钮都已就位。

**每一期都要能单独玩**，不许出现「做完三期才好玩」的东西。

## 十二、怎么验证机制真的活着

记忆里 `dead-mechanic-audit` 那一条：**胜率表正常不代表机制跑过。**
`tools/lord.ts` 要扩成一个**计数器**，跑十年之后打印：

```
呈报发出              412 件
　批准                186
　留中                 97
　驳回                 64
　过期未理             65
自作主张（未请令出兵）   11 次
「不再上报」的人         4 人
叛逃                    2 人
望：  38 → 61 → 44 → 72
挟天子                第 2140 日
```

任何一行是 **0**，那一条就是死的，当场回去查 —— 不许拿「平衡表好看」结案。

同时补测试：
- 心气跌破线之后，呈报频率**确实**下降（不是只有那个隐藏数在动）
- 令的传递：治所发出的兴修令，在到达之前 `dev` **不许**变
- 虚报：账面粮与 `node.grain` 在有贪吏时**必须**对不上

## 十三、这套东西为什么不违反三条硬规矩

1. **不做数值面板** —— 心气是一句话，望是评语，态度是一个词，人还是画像 + 评语 + 擅长标签。
   而且更进一步：**连兵和粮都变成了不可尽信的账。**
2. **资源是对象** —— 主公新增的资源是「人」和「望」，两者都有视觉呈现：
   人在堂上站班，望是天下人的一句话。粮车在图上真的走。
3. **楔子只改权重** —— 献策、名分、时局，三样全部只拧现成公式上的乘数，
   一条新规则也没有岔出去。
